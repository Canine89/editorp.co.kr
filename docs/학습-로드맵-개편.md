## 추천 기준

최신 영상 순서보다 선수 개념과 학습 결과를 우선한다. 기초 경로 다음에 클로드·커서·코덱스 중 목적에 맞는 도구 하나를 선택하고, 작은 결과물 완성 후 자동화와 하네스로 확장한다.

1. AI 기초: 모델·토큰 → 컨텍스트 → 터미널 → 서버·포트 → 도구 선택.
2. 클로드: 핵심 메뉴 → 문서 작업 → 아티팩트 → 스킬 → 코워크.
3. 커서: 설치 → 계획 → 웹 기초 → 디자인 규칙 → 메모 앱 → 배포.
4. 코덱스: 설치 → 페이지 제작 → 프로젝트 지침 → 디자인 규칙 → 하네스.
5. 업무 자동화: MCP → 커넥터 → 한글 스킬 제작 → 엑셀 → 구글 도구 연결.
6. 에이전트 심화: 하네스 개념과 실습 → 스킬 관리 → 훅 → 오르카 → 워크트리 → 반복 작업과 검토.

각 경로에 대상, 선수 지식, 실습 목표, 다음 경로를 명시한다. 시청 시간은 확인된 동영상 길이를 합산하며, 도구의 과거 요금·화면과 현재 상태를 동일하다고 단정하지 않는다.

## 운영 데이터

운영 로드맵의 원본은 기존과 동일하게 Firestore의 roadmaps 컬렉션이다. 추천 경로 역시 같은 컬렉션에 curation 메타데이터를 추가하여 기존 관리자에서 제목·설명·강의 순서·활성 상태를 수정할 수 있다. 관리자 저장 시 메타데이터를 유지한다. 관리자 이메일은 기존 lib/admin.ts의 단일 출처를 유지한다.

초기 추천 경로는 data/learning-paths.json에 있다. lib/learning-data.ts는 저장된 추천 경로를 우선 읽고, 최초 등록 전에는 초기 경로를 표시한다. 등록된 경로가 모두 비활성인 경우 초기 경로로 되돌아가지 않는다. 기존 data/roadmap.json을 운영 원본으로 사용하지 않는다.

배포 환경에 추천 경로를 처음 등록할 때:

```sh
node scripts/import-learning-paths.mjs
node scripts/import-learning-paths.mjs --apply
```

첫 명령은 로컬 미리보기만 한다. 두 번째 명령은 Firebase 환경 변수를 이용해 없는 문서만 트랜잭션으로 추가한다. 이미 존재하는 6개 추천 경로나 기존 로드맵은 덮어쓰지 않는다. 카테고리 설정은 기존 값을 합쳐 보존한다. 이번 작업에서 운영 Firestore에 직접 쓰거나 배포하지 않았다.

진도 키 completed-nodes-{roadmap.id}는 기존과 동일하다. 마지막 선택 강의는 last-node-{roadmap.id}에 저장한다. 손상된 저장값, 중복 ID, 삭제된 강의 ID는 걸러내며, 저장이 차단되어도 학습 화면은 동작한다.

## 검증 결과

- 프로덕션 빌드와 변경한 파일의 ESLint 검사 통과.
- 잠금 파일 불일치를 보정했고 `npm ci --dry-run --ignore-scripts` 통과.
- 284개 영상 ID 중복, 6개 추천 경로의 33개 수록 강의, 후원자 전용 제외, 다음 경로, 기존 스키마 호환성 검증.
- 검색어+라이브 필터, 결과 없음, 재생목록 17개, 페이지 범위 보정, 홈의 목표별 필터 검증.
- 학습 완료 시 다음 강의 이동, 새로고침 후 마지막 강의와 진도 복원, 잘못된 JSON 구조 및 차단된 저장소에서의 학습 동작 검증.
- 소개의 집필 도서 7권·강의 이력 31건을 실제 렌더링에서 확인.
- 데스크톱과 390px 모바일, 밝은/어두운 테마에서 화면 확인. 홈·소개·학습·검색 화면의 가로 넘침 없음.
- 공개 페이지 정상 응답, 잘못된 학습 경로 404, 비로그인 관리자 접근 307 리디렉션 확인.
- Lighthouse 모바일 시뮬레이션: 성능 94, 접근성 100, 권장사항 100, 검색 최적화 100. FCP 1.1초, LCP 3.2초, 총 차단 시간 0ms, CLS 0. 로컬 프로덕션 서버 기준이며 실제 배포 환경에서는 달라질 수 있다.
- 로컬 인증 세션 확인에 미리보기 전용 NEXTAUTH_SECRET을 환경 변수로 사용했다. 실제 Google 로그인과 운영 Firestore 쓰기는 수행하지 않았다.
- 전체 저장소 ESLint에는 기존 관리자/API/도서 편집기 오류가 남아 있다. 이번 변경 파일의 검사 결과와 구분한다.

미리보기는 `http://localhost:3107`에서 실행했다. 새로 실행하려면 `npm run dev -- --port 3107`을 사용한다. 인증 기능 확인에는 프로젝트의 실제 인증 환경 설정이 필요하다.
