지금까지는 파이썬이 준비한 모듈을 가져왔습니다. 우리가 직접 만든 함수도 별도의 파일에 저장하면 다른 프로그램에서 다시 사용할 수 있습니다. 이번에는 인사말 함수를 별도의 모듈로 분리하고, 모듈을 가져올 때 확인용 코드까지 함께 실행되는 이유도 살펴보겠습니다. 그런 다음 필요한 코드만 실행되도록 구분하는 방법까지 알아봅시다.

> **미리 알아두세요!**
>
> - 직접 만든 파이썬 파일도 다른 파일에서 모듈로 가져올 수 있습니다.
> - 모듈을 가져오면 해당 파일의 코드가 위에서부터 실행됩니다.

## 함수가 들어 있는 모듈 만들기

먼저 인사말을 만드는 함수를 message_tools.py 파일에 작성하겠습니다. 함수가 제대로 동작하는지 확인할 수 있도록 테스트용 코드도 함께 작성한 뒤 파일을 직접 실행해봅시다.

```python filename="message_tools.py"
def make_greeting(name):     # ➊ 인사말 함수 정의
  return f"{name} 님, 반갑습니다!"

print(make_greeting("바로"))  # ➋ 함수 동작 확인
```

**실행 결과**

```text
바로 님, 반갑습니다!
```

❶ make_greeting( ) 함수는 이름을 전달받아 인사말 문자열을 반환합니다. 이 함수는 나중에 다른 파일에서 가져와 사용하겠습니다.

❷ message_tools.py 파일을 직접 실행하여 함수가 제대로 동작하는지 확인합니다.

코드 자체는 아주 단순하지만 이번 실습의 핵심은 이 파일에 작성한 함수를 다른 파일로 가져가 사용하는 것입니다. 이제 실제로 모듈을 가져와봅시다.

## 만든 모듈 가져오기

이제 message_tools.py와 같은 폴더에 11-08-greeting_app.py 파일을 만듭니다. 두 파일이 같은 폴더에 있으면 message_tools.py의 파일 이름에서 .py를 뺀 message_tools를 모듈 이름으로 사용할 수 있습니다. 즉, 11-08-greeting_app.py에서 message_tools 모듈을 가져오면 message_tools.py에 작성한 함수와 코드를 사용할 수 있습니다. 다음 코드를 작성하고 실행하며 확인해봅시다.

```python filename="11-08-greeting_app.py"
import message_tools                             # ➊ 직접 만든 모듈 가져오기
message = message_tools.make_greeting("요즘")    # ➋ 모듈 함수 호출
print(message)
```

**실행 결과**

```text
바로 님, 반갑습니다!
요즘 님, 반갑습니다!
```

❶ import message_tools를 작성하여 message_tools.py 파일을 message_tools 모듈로 가져왔습니다. 다시 말하지만 이 예제에서는 11-08-greeting_app.py와 message_tools.py 파일이 같은 폴더에 있어야 합니다. 여기서 중요한 점이 하나 있습니다. 파이썬이 모듈을 처음 가져올 때는 그 모듈 파일에 작성된 코드를 위에서부터 실행합니다. 따라서 message_tools.py에 함수 확인용으로 작성해둔 다음 코드도 함께 실행되어 테스트용 인사말도 출력됩니다.

```python
print(make_greeting("바로"))
```

❷ message_tools.make_greeting( )처럼 모듈 이름 뒤에 점을 찍어 make_greeting( ) 함수를 호출했습니다. 이처럼 직접 만든 파이썬 파일도 모듈로 만들어 다른 파일에서 가져와 사용할 수 있습니다.

그런데 한 가지 문제가 있습니다. import message_tools를 실행하면 message_tools.py의 코드가 실행되기 때문에 테스트용 print( ) 코드까지 함께 실행됩니다. 그렇다고 테스트용 코드를 아예 지우자니 다음과 같은 고민이 생깁니다.

1. 모듈을 계속 수정할 예정이라 print( ) 함수를 이용한 테스트 코드는 남겨두고 싶습니다. 2. 하지만 테스트 코드를 남겨두면 프로그램을 실행해 모듈을 가져올 때마다 print( ) 함수가 함께 실행되어 불편합니다. 3. 그렇다고 지워버리면 나중에 테스트할 때 print( ) 함수를 다시 작성해야 합니다.

이럴 때는 모듈 파일을 직접 실행했을 때만 테스트용 코드가 실행되도록 구분하면 됩니다.

## 파일을 직접 실행할 때만 테스트하기

파이썬에서는 실행되는 모든 파이썬 파일에 __name__이라는 특별한 이름의 숨겨진 변수가 자동으로 만들어집니다. 그리고 파일을 직접 실행했는지, 다른 파일에서 모듈로 가져왔는지에 따라 __name__에 들어가는 값이 달라집니다.

예를 들어 터미널에서 다음과 같이 message_tools.py 파일을 직접 실행해봅시다. 이 경우 python message_tools.py와 같이 명령어로 파일을 직접 실행하면 파이썬은 message_tools.py의 __name__ 변수에 "__main__"이라는 문자열을 저장합니다.

![](/books/python-intro/p512-314.webp)

반면 다른 파일에서 import message_tools를 실행하여 모듈로 가져오면 어떨까요? 이 경우 message_tools.py 안의 __name__에는 "__main__"이 아니라 모듈 이름인 "message_tools"가 들어갑니다. 정리하면 다음과 같습니다.

- message_tools.py를 직접 실행하면 → __name__ == "__main__"

- message_tools를 다른 파일에서 가져오면 → __name__ == "message_tools"

이 차이를 이용하면 파일을 직접 실행했을 때만 테스트용 코드를 실행하도록 만들 수 있습니다. 우선 message_tools.py 파일의 테스트용 print( ) 코드를 다음과 같이 수정해봅시다.

![](/books/python-intro/p513-315.webp)

```python filename="message_tools.py"
def make_greeting(name):              # ➊ 인사말 함수 정의
  return f"{name} 님, 반갑습니다!"

if __name__ == "__main__":            # ➋ 직접 실행했는지 확인
  print(make_greeting("바로"))
```

![](/books/python-intro/p513-316.webp)

이제 터미널에서 python message_tools.py 명령으로 파일을 직접 실행하면 테스트용 코드가 정상적으로 실행될 겁니다. 파일을 직접 실행했으므로 __name__에 "__main__"이 들어가고, if문의 조건이 True가 되기 때문입니다.

반대로 11-08-greeting_app.py를 실행해 import message_tools로 모듈을 가져오면 상황이 달라집니다. 이때 message_tools.py 안의 __name__에는 "__main__"이 아니라 "message_tools"가 들어갑니다. 따라서 조건이 False가 되어 테스트용 print(make_greeting("바로")) 코드는 실행되지 않습니다.

```python filename="11-08-greeting_app.py"
import message_tools
message = message_tools.make_greeting("요즘")
print(message)
```

모듈의 본체인 파일을 실행하지만 그 파일의 print( ) 함수는 실행되지 않습니다

**실행 결과**

```text
요즘 님, 반갑습니다!
```

이처럼 __name__의 값을 확인하면 파일을 직접 실행할 때만 필요한 테스트용 코드와 다른 파일에서 가져와 사용할 함수나 클래스 같은 기능을 구분할 수 있습니다.

![](/books/python-intro/p514-317.webp)

> **바로 핵심 요약**
>
> - 직접 만든 .py 파일도 import 문으로 가져와 사용할 수 있습니다.
> - 직접 만든 모듈을 가져올 때는 파일 이름에서 .py를 뺀 이름을 사용합니다.
> - 파일을 직접 실행하면 해당 모듈의 __name__은 "__main__"이 됩니다.
> - if __name__ == "__main__":을 사용하면 파일을 직접 실행할 때만 실행할 코드를 구분할 수 있습니다.
