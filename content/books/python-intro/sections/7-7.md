여기서는 함수가 자기 자신을 부르는 **재귀 함수**를 알아봅니다. 처음에는 조금 복잡하게 느껴질 수 있지만 언제 멈추는지 종료 조건을 잘 살펴보면 어렵지 않습니다. 카운트다운과 피보나치 수열을 코드로 만들어보면서 재귀 함수가 어떻게 동작하는지 천천히 익혀봅시다.

> **미리 알아두세요!**
>
> - 재귀 함수는 자기 자신을 호출하는 함수로, 반드시 종료 조건이 필요합 니다.
> - 종료 조건이 없으면 호출 한계에 닿아 Recur sionError가 발생합니다.

## 함수가 자기 자신을 부르는 재귀 함수 알아보기

지금까지 함수 안에서 다른 함수를 호출하거나 정의해봤습니다. 그런데 함수는 실행 도중 자기 자신을 호출할 수도 있습니다. 이처럼 **자기 자신을 호출하는 함수를 재귀 함수라고 부릅니다.**

![](/books/python-intro/p337-224.webp)

예를 들어 로켓을 발사하기 전에 3, 2, 1, 발사!와 같이 카운트다운하는 상황을 함수로 만들면 다음과 같습니다.

```python filename="07-29-recursive_countdown.py"
def countdown(n):
  if n == 0:        # 종료 조건: 0이 되면 멈춘다
    print("발사!")
    return
  print(n)          # 지금 숫자를 외치고
  countdown(n - 1)  # 1 줄여서 자기 자신을 다시 부른다

countdown(3)
```

**실행 결과**

```text
3
2
1
발사!
```

여기서 집중해서 볼 부분은 countdown( ) 함수의 코드 블록 맨 앞에 있는 if n == 0:입니다. 이 코드가 재귀 함수를 멈추게 하는 종료 조건입니다. 함수 실행 과정을 차례대로 살펴봅시다.

1. countdown(3)을 부르면2. n이 0이 아니므로 if n == 0:을 건너뜁니다. 3. print(n)으로 3을 출력한 뒤4. 다시 countdown(2)를 부릅니다. 5. countdown(2)는 if n == 0:을 건너뛰고 2를 출력하고6. 다시 countdown(1)을 부릅니다. 7. countdown(1)은 if n == 0:을 건너뛰고 1을 출력하고8. 다시 countdown(0)을 부릅니다. 9. 마침내 countdown(0)에서 if n == 0:이 참이 되어 코드 블록의 print(“발사!”)가 실행되고10. return으로 함수를 종료합니다.

![](/books/python-intro/p338-225.webp)

이처럼 함수가 자기 자신을 반복해서 부르다가 종료 조건을 만나 멈추도록 만들어진 함수를 재귀 함수라고 부릅니다.

### 종료 조건이 없으면 어떻게 되는지 알아보기

앞서 재귀 함수에는 호출을 멈추는 종료 조건이 필요하다고 했습니다. 그런데 종료 조건을 빼더라도 함수 정의 자체에는 문제가 없습니다. 문제는 함수를 실제로 실행했을 때 생깁니다. 예를 들어 앞에서 만든 countdown( ) 함수에서 if n == 0:이 없다면 어떻게 될까요? 아마도 countdown(n - 1)이 계속 실행되면서 n은 3, 2, 1, 0, -1처럼 계속 작아지고, 함수는 자기 자신인 countdown( ) 함수를 반복해서 호출할 겁니다.

하지만 파이썬은 재귀 호출이 쌓일 수 있는 깊이에 제한을 두고 있습니다. 이 한계에 도달하면 더 이상 함수를 호출하지 않고 RecursionError라는 오류를 내며 멈춥니다. 따라서 실제로는 영원히 무한 반복되는 것이 아니라 파이썬이 허용하는 재귀 호출 한계에 도달하면 오류와 함께 멈추게 되는 거죠. 정말 그런지 다음 코드를 실행해봅시다.

```python filename="07-30-countdown_without_base_case.py"
def countdown(n):
  print(n)
  countdown(n - 1)  # 종료 조건이 없어 끝없이 자신을 부른다

countdown(3)
```

**실행 결과**

```text
3
2
1
0
-1
-2
(... 숫자가 계속 줄어들며 출력 ...)
-995
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded
```

코드를 실행하면 약 1,000번 실행되다가 RecursionError: maximum recursion depth exceeded와 같은 오류 메시지를 출력하고 종료됩니다. 이론상으로는 무한하게 실행되어야 하지만 파이썬이 정해둔 호출 한계가 있어 종료되는 겁니다. 다만 실제 오류가 발생하기까지의 호출 횟수나 마지막에 출력되는 숫자는 파이썬 버전과 실행 환경에 따라 달라질 수 있습니다. 따라서 여러분 화면에 나타나는 숫자가 책과 정확히 같지 않아도 괜찮습니다.

이런 이유로 재귀 함수를 만들 때는 반드시 다음을 설계해두는 것이 좋습니다.

1. 재귀 호출을 멈추는 종료 조건을 만듭니다. 2. 재귀 호출을 거듭할수록 종료 조건에 가까워지도록 함수를 만듭니다.

종료 조건이 있더라도 호출할 때마다 종료 조건에서 멀어진다면 함수는 멈추지 못합니다. 예를 들어 n이 0이 되면 멈추도록 해놓고 countdown(n + 1)처럼 작성한다면 n은 계속 커지므로 종료 조건에 도달하지 못합니다. 결국 이 경우에도 재귀 호출 한계에 도달하여 RecursionError가 발생합니다.

종료 조건의 중요성을 알았으니 이번에는 조금 더 복잡한 재귀 함수를 살펴보겠습니다.

### 피보나치 수열로 알아보는 종료 조건

앞에서 countdown( ) 예제를 통해 함수가 자기 자신을 호출하는 재귀 함수의 원리를 살펴봤습니다. 특히 강조한 내용은 종료 조건이었습니다. 종료 조건이 없거나 종료 조건에 도달할 수 없다면 함수가 자기 자신을 계속 호출하다가 결국 RecursionError가 발생한다는 것도 확인했죠. 이번에는 앞의 두 수를 더해 다음 수를 만드는 피보나치 수열 1, 1, 2, 3, 5, 8...을 재귀 함수로 만들어보면서 종료 조건이 어떻게 사용되는지 연습해봅시다.

> **NOTE**
>
> 여기서는 피보나치 수열의 첫 번째 수와 두 번째 수를 각각 1로 두겠습니다.

피보나치 수열을 함수로 구현하는 방법은 다양하지만 직관적으로 이해하기 쉬운 것은 앞의 두 수를 더하면 그다음 수가 되는 다음과 같은 형태입니다.

- fibonacci(n) = fibonacci(n - 1) + fibonacci(n - 2)

즉, n번째 피보나치 수를 구하려면 바로 앞의 두 피보나치 수를 구해 더하면 됩니다. 따라서 한 번의 함수 호출에서 자기 자신을 두 번 호출하는 구조가 만들어집니다. 함수는 다음과 같이 작성할 수 있습니다.

```python filename="07-31-recursive_fibonacci.py"
def fibonacci(n):
  if n == 1 or n == 2:
    return 1

  return fibonacci(n - 1) + fibonacci(n - 2)

print(f"2번째 수 : {fibonacci(2)}")
print(f"5번째 수 : {fibonacci(5)}")
print(f"10번째 수 : {fibonacci(10)}")
```

**실행 결과**

```text
2번째 수 : 1
5번째 수 : 5
10번째 수 : 55
```

처음 보면 조금 복잡하게 느껴질 수 있습니다. 여기서 가장 먼저 살펴볼 부분은 if n == 1 or n == 2:입니다. 피보나치 수열에서 첫 번째 수와 두 번째 수는 모두 1입니다. 따라서 n이 1 또는 2라면 더 이상 자기 자신을 호출하지 않고 1을 반환합니다. 이 부분이 재귀 호출을 멈추는 종료 조건입니다. 재귀 호출을 할 때마다 n의 값이 점점 줄어들어 언젠가는 종료 조건에 다다르게 됩니다. 그렇다면 fibonacci(5)를 호출하면 어떻게 될까요? 앞에서 살펴본 카운트다운과 달리 피보나치 함수는 한 번 호출할 때 자기 자신을 두 번 호출하므로 호출이 한 줄로 이어지는 것이 아니라 여러 갈래로 나뉩 니다.

1. fibonacci(5) → 종료 조건이 아니므로 fibonacci(4) + fibonacci(3)을 부릅니다 (n: 5 → 4, 3). 2. fibonacci(4) → 다시 fibonacci(3) + fibonacci(2)를 부릅니다(n: 4 → 3, 2). 3. fibonacci(3) → 다시 fibonacci(2) + fibonacci(1)을 부릅니다(n: 3 → 2, 1). 4. fibonacci(2) → n이 2이므로 종료 조건에 해당해 자기 자신을 부르지 않고 1을 반환합 니다. 5. fibonacci(1) → n이 1이므로 종료 조건에 해당하므로, 마찬가지로 1을 반환합니다.

중요한 점은 재귀 호출을 따라갈수록 n의 값이 n - 1 또는 n - 2로 작아져 결국 2나 1에 닿는 순간 멈춘다는 것입니다. 그리고 멈춰서 돌려준 1들이 거꾸로 더해져 올라오면서 최종적으로 5라는 값이 완성됩니다. 즉, **실제 덧셈은 종료 조건으로부터 거슬러 올라오면서 일어납니다.**

재귀에서 특히 헷갈리는 부분이 있습니다. 함수를 호출하며 아래로 내려갈 때는 필요한 값을 계속 더 작은 문제로 나누고, 덧셈 결과는 종료 조건에서 값이 반환되기 시작하면서 하나씩 완성된다는 점입니다. 앞에서 보듯 fibonacci(5)는 5라는 답을 바로 내놓지 못합니다. fibonacci(4) + fibonacci(3)의 결과를 기다립니다. fibonacci(4) 역시 fibonacci(3) + fibonacci(2)의 결과가 필요하고, fibonacci(3)도 다시 fibonacci(2) + fibonacci(1)의 결과를 기다립니다. 이렇게 재귀 호출이 이어지다가 fibonacci(2)와 fibonacci(1)이 종료 조건에 도달하면 1을 반환합니다. 그제야 기다리던 함수들이 반환받은 값을 더해 자신의 결과를 완성하고, 그 답을 다시 자신을 호출한 함수에 반환합니다. 실제 숫자로 따라가 보면 이렇습니다.

1. fibonacci(1) = 12. fibonacci(2) = 13. fibonacci(3) = fibonacci(2) + fibonacci(1) = 1 + 1 = 24. fibonacci(4) = fibonacci(3) + fibonacci(2) = 2 + 1 = 35. fibonacci(5) = fibonacci(4) + fibonacci(3) = 3 + 2 = 5즉 ‘1들이 거꾸로 더해져 올라온다’는 것은, 맨 아래에서 돌려준 1들이 한 단계 위에서 2가 되고, 그 2가 다시 위에서 3이 되는 식으로 밑에서부터 차곡차곡 합쳐지며 결국 맨 위의 5가 된다는 뜻입니다.

비유하자면 사장이 직원에게 “5번 값 구해 와”라고 일을 시킨 상황과 비슷합니다. 직원은 혼자 답을 알 수 없어 다른 직원들에게 “4번 값을 구해 와”, “3번 값을 구해 와”라고 일을 나눠줍니다. 그 직원들도 다시 더 작은 번호의 값을 구하도록 일을 나눕니다. 그러다가 가장 아래 단계에서 “1번이요? 그건 1입니다.”, “2번이요? 그것도 1입니다.”라는 답이 나오면 그때부터 결과가 위로 전달됩니다. 각 단계에서는 전달받은 두 결과를 더해 자신의 답을 만든 뒤 다시 위 단계로 돌려줍니다. 이 과정이 반복되어 마지막에는 사장이 5라는 최종 결과를 받게 됩니다.

이제 재귀 함수가 자기 자신을 호출해 문제를 더 작은 문제로 나누고, 종료 조건에서 얻은 결과를 이용해 다시 답을 완성해가는 구조 라는 것이 조금 더 분명해졌을 겁니다.

>
> - 재귀 함수는 함수가 자기 자신을 호출하는 방식으로 동작하며, 재귀 호출이 끝날 수 있도록 종료 조건이 있어야 합니다.
> - 종료 조건이 없거나 재귀 호출이 종료 조건에 가까워지지 않으면 호출이 계속되어, 결국 파이썬이 정해둔 재귀 호출 한계에 도달하고 RecursionError가 발생합니다.
