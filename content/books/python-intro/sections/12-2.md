먼저 값의 복사부터 알아보겠습니다. 에서 별칭(b = a)과 얕은 복사(b = a.copy( ))를 살펴봤지만, 리스트 안에 또 다른 리스트가 들어 있는 중첩 구조에서는 얕은 복사만으로 해결되지 않는 경우가 있습니다. 이번 절에서는 그때 미뤄 두었던 이야기를 이어서, 값을 복사한다는 것이 실제로 어떤 의미인지 자세히 살펴보고 함수의 기본값에 리스트를 사용할 때 생길 수 있는 문제도 함께 알아보겠습니다.

> **미리 알아두세요!**
>
> - 별칭은 값을 복사하는 것이 아니라 같은 값에 이름표를 하나 더 붙이는 것입니다.
> - 안쪽까지 복사하려면 copy 모듈의 deepco py( ) 함수를 사용합니다.

## b = a, 별칭 돌아보기

이미 a에 리스트를 저장한 뒤 b = a와 같이 a의 리스트를 b로 복사하는 코드를 실습한 적이 있습니다. 이것을 별칭이라고 설명했습니다. 시간이 조금 지나 기억이 흐릿할 수도 있으니 다음 코드를 실행해 별칭이 무엇이었는지 다시 확인해봅시다.

![](/books/python-intro/p550-340.webp)

```python filename="12-01-name_tag.py"
a = [1, 2, 3]
b = a                   # ➊ 별칭, 이름표만 붙이기
b.append(4)             # ➋ b를 통해 같은 리스트에 값 추가
print(f"a: {a}")
print(f"b: {b}")
```

**실행 결과**

```text
a: [1, 2, 3, 4]
b: [1, 2, 3, 4]
```

❶ b = a는 [1, 2, 3]이라는 리스트를 새로 하나 만들어 복사하는 것이 아닙니다. a와 b가 같은 리스트 인스턴스를 가리키게 됩니다.

❷ 따라서 b를 통해 리스트에 값을 추가하면 a로 확인해도 같은 변경 결과가 보입니다. a와 b가 모두 같은 리스트를 가리키고 있기 때문입니다. 그 결과 두 변수로 확인한 값 모두 [1, 2, 3, 4]가 됩니다.

![](/books/python-intro/p551-341.webp)

## 얕은 복사, copy( ) 돌아보기

그렇다면 원본과는 별개의 리스트를 만들고 싶을 때는 어떻게 해야 할까요? 앞에서는 리스트의 copy( ) 메서드를 사용했습니다.

```python filename="12-02-shallow_copy.py"
a = [1, 2, 3]
b = a.copy()             # ➊ 새 리스트를 만들어 요소를 옮겨 담기
b.append(4)
print(f"a: {a}")
print(f"b: {b}")
```

**실행 결과**

```text
a: [1, 2, 3]
b: [1, 2, 3, 4]
```

❶ a.copy( )를 실행하면 새로운 바깥쪽 리스트가 만들어집니다. 따라서 a와 b는 서로 다른 리스트 인스턴스를 가리키게 됩니다.

단순한 리스트라면 이것만으로도 원본과 복사본을 따로 다룰 수 있습니다. 그런데 리스트 안에 또 다른 리스트가 들어 있다면 이야기가 조금 달라집니다. copy( )가 ‘얕은 복사’라고 불리는 이유도 여기에서 드러납니다.

## copy( )로는 부족한 경우? 중첩 리스트 복사!

이번에는 반 학생들의 점수를 모아둔 중첩 리스트가 있다고 생각해봅시다. 리스트 안에 또 다른 리스트가 들어 있는 형태입니다. 다음 코드를 실행해봅시다.

```python filename="12-03-shallow_copy_problem.py"
scores = [[80, 90], [70, 100]]
copied = scores.copy()      # ➊ 얕은 복사
copied[0].append(100)       # ➋ 복사본을 통해 공유 중인 안쪽 리스트에 값 추가
print(f"scores: {scores}")
print(f"copied: {copied}")
```

**실행 결과**

```text
scores: [[80, 90, 100], [70, 100]]
copied: [[80, 90, 100], [70, 100]]
```

❶ 리스트의 copy( ) 메서드로 복사했습니다. 겉으로 보기에는 [[80, 90], [70, 100]]이라는 내용이 새로운 리스트에 그대로 복사된 것처럼 보입니다.

❷ 하지만 복사본의 안쪽 리스트에 100을 추가해보면 원본인 scores의 내용도 함께 바뀝니다.

왜 이런 일이 벌어질까요? copy( )를 사용하면 바깥쪽 리스트는 새로 만들어지지만, 그 안에 들어 있는 요소들은 기존 인스턴스를 그대로 가리키기 때문입니다. 이 예제에서 바깥 리스트는 새로 만들어졌지만 그 안에 들어 있는 [80, 90], [70, 100] 같은 리스트 인스턴스는 원본과 복사본이 함께 가리키고 있습니다. 따라서 안쪽 리스트의 내용을 변경하면 원본과 복사본 모두에서 그 변화가 보입니다. 이처럼 가장 바깥쪽 인스턴스만 새로 만들고 내부의 인스턴스는 원본과 공유하는 방식을 얕은 복사라고 합니다. 바깥 상자는 새로 만들었지만, 상자 안의 물건은 원본 상자와 함께 사용하는 셈입니다. 내부의 인스턴스까지 원본과 분리하려면 깊은 복사를 사용해야 합니다.

## 깊은 복사, copy.deepcopy( )

중첩 리스트처럼 내부 인스턴스까지 독립적으로 복사하고 싶다면 deepcopy( )를 사용할 수 있습니다. 이를 깊은 복사라고 합니다.

```python filename="12-04-deep_copy.py"
import copy                        # ➊ copy 모듈 가져오기

scores = [[80, 90], [70, 100]]
copied = copy.deepcopy(scores)     # ➋ 깊은 복사
copied[0].append(100)
print(f"scores: {scores}")
print(f"copied: {copied}")
```

**실행 결과**

```text
scores: [[80, 90], [70, 100]]
copied: [[80, 90, 100], [70, 100]]
```

❶ deepcopy( ) 함수는 파이썬 표준 라이브러리인 copy 모듈에 들어 있습니다.

❷ deepcopy( )는 바깥 리스트뿐 아니라 안에 들어 있는 리스트까지 모두 새로 복사합니다. 그래서 이번에는 원본 scores가 변경되지 않습니다.

여기까지의 내용을 간단히 정리하면 다음과 같습니다.

- 같은 인스턴스를 함께 가리키는 별칭
- 바깥쪽 인스턴스만 새로 만드는 얕은 복사 copy( )
- 내부에 연결된 인스턴스까지 모두 복사하는 깊은 복사 copy.deepcopy( )

![](/books/python-intro/p553-342.webp)

리스트나 딕셔너리 안에 또 다른 리스트나 딕셔너리처럼 변경할 수 있는 인스턴스가 중첩되어 있고, 원본과 복사본을 서로 독립적으로 바꾸고 싶다면 deepcopy( )를 떠올리면 됩니다.

> **NOTE**
>
> 숫자나 문자열처럼 값을 바꿀 수 없는 자료형은 이런 고민을 할 필요가 없습니다. 값을 바꿀 수 없으니 원본이 함께 바

뀌는 일도 생기지 않기 때문입니다. 이 문제는 리스트, 딕셔너리, 집합처럼 값을 바꿀 수 있는 자료형에서만 생깁니다.

## 함수의 기본값에 리스트를 쓰면 안 되는 이유

값을 바꿀 수 있는 자료형 때문에 생기는 대표적인 함정이 하나 더 있습니다. 함수의 기본값 매개변수에 리스트를 넣으면 어떻게 되는지 확인해봅시다.

```python filename="12-05-mutable_default.py"
def add_item(item, basket=[]):   # ➊ 기본값으로 빈 리스트
  basket.append(item)
  return basket

print(add_item("사과"))
print(add_item("바나나"))         # ➋ 새 장바구니를 기대했지만
```

**실행 결과**

```text
['사과']
['사과', '바나나']
```

❶ 장바구니를 전달하지 않으면 빈 리스트에서 시작하도록 매개변수의 기본값을 [ ]로 정했습니다.

❷ 함수를 처음 호출해 "사과"를 추가한 뒤 다시 호출해 "바나나"를 추가해보겠습니다. 두 번째 호출에서는 새로운 빈 장바구니에서 시작할 것 같지만 앞에서 넣은 "사과"가 그대로 남아 있습니다.

조금 이상하지 않나요? 기본값으로 작성한 빈 리스트 [ ]는 함수를 호출할 때마다 새로 만들어질 것처럼 보이지만 실제로는 그렇지 않습니다. 매개변수의 기본값은 함수를 호출할 때가 아니라 정의할 때 한 번만 만들어지기 때문입니다. 따라서 add_item( ) 함수를 호출할 때마다 새로운 리스트를 사용하는 것이 아니라, 처음 만들어진 하나의 리스트를 계속 사용합니다. 첫 번째 호출에서 이 리스트에 "사과"를 추가했으므로 두 번째 호출에서는 같은 리스트에 "바나나"가 이어서 추가됩니다. 이처럼 리스트와 같이 값을 변경할 수 있는 인스턴스는 매개변수의 기본값으로 직접 사용하지 않는 것이 좋습 니다.

### 함수 호출 시 리스트를 매번 새로 만들고 싶다면?

그렇다면 함수가 호출될 때마다 새로운 리스트를 만들려면 어떻게 해야 할까요? 이럴 때는 기본값을 None으로 두고, 함수 안에서 필요한 경우 새 리스트를 만들면 됩니다.

![](/books/python-intro/p554-343.webp)

```python filename="12-06-default_none.py"
def add_item(item, basket=None):   # ➊ 기본값은 None
  if basket is None:               # ➋ 호출할 때마다 새 리스트 만들기
    basket = []
  basket.append(item)
  return basket

print(add_item("사과"))
print(add_item("바나나"))
```

**실행 결과**

```text
['사과']
['바나나']
```

❶ 매개변수의 기본값을 아무것도 없는 None으로 정했습니다.

❷ 장바구니가 전달되지 않아 basket이 None이라면 그때 새로운 빈 리스트를 만듭니다. 따라서 장바구니를 전달하지 않고 호출하면 매번 새로운 빈 장바구니에서 시작합니다.

> **NOTE**
>
> 값이 None인지 확인할 때는 일반적으로 basket == None보다 basket is None처럼 is를 사용합니다.

## 값 복사 연습하기

지금까지 살펴본 복사 방법을 직접 코드로 연습해봅시다. 어떤 경우에 얕은 복사만으로 충분하고, 어떤 경우에 깊은 복사가 필요한지 실행 결과를 비교해보세요.

## 연습 01 원본을 지키며 리스트 복사하기

과일 목록을 하나 복사해 백업을 만든 뒤 원본에 값을 추가해봅시다.

```python filename="12-07-copy_practice.py"
fruits = ["사과", "바나나"]
backup = fruits.copy()      # ➊ 얕은 복사로 백업
fruits.append("딸기")
print(f"fruits: {fruits}")
print(f"backup: {backup}")
```

**실행 결과**

```text
fruits: ['사과', '바나나', '딸기']
backup: ['사과', '바나나']
```

❶ fruits.copy( )로 원본과 내용이 같은 새 리스트를 만들어 backup에 저장했습니다. 따라서 원본 리스트에 "딸기"를 추가해도 backup은 바뀌지 않습니다. 이 예제처럼 리스트의 요소가 문자열과 같은 변경 불가능한 값이라면 얕은 복사만으로 충분합니다.

## 연습 02 딕셔너리를 품은 리스트 복사하기

이번에는 리스트 안에 딕셔너리가 들어 있고, 그 딕셔너리 안에 다시 리스트가 들어 있습니다. 내부에 있는 인스턴스까지 독립적으로 복사하려면 깊은 복사가 필요합니다. 코드를 직접 입력하며 다시 확인해봅시다.

```python filename="12-08-deepcopy_practice.py"
import copy

students = [{"name": "바로", "scores": [80, 90]}]
backup = copy.deepcopy(students)    # ➊ 깊은 복사
students[0]["scores"].append(100)   # ➋ 원본의 안쪽 리스트만 수정
print(f"students: {students}")
print(f"backup: {backup}")
```

**실행 결과**

```text
students: [{'name': '바로', 'scores': [80, 90, 100]}]
backup: [{'name': '바로', 'scores': [80, 90]}]
```

❶ 리스트 안에 딕셔너리가 있고 그 안에 다시 리스트가 들어 있으므로 deepcopy( )를 사용했습 니다.

❷ 원본인 students의 scores 리스트에 100을 추가했습니다. backup은 deepcopy( )로 내부 인스턴스까지 따로 복사했으므로 백업의 점수는 [80, 90]으로 그대로 유지됩니다. 만약 copy( )로 얕은 복사했다면 바깥 리스트만 새로 만들어지고 안쪽 딕셔너리와 그 안의 scores 리스트는 원본과 백업이 함께 가리키므로 backup에도 100이 추가되었을 것입니다.

## 연습 03 기본값을 None으로 바꾸기

앞서 변경 가능한 내부 인스턴스를 함께 참조하지 않도록 깊은 복사를 사용해봤습니다. 이번에는 같은 원리 때문에 생기는 함수 기본값 문제를 연습해보겠습니다. 메모를 하나씩 추가하는 함수를 만들어봅시다. 함수를 여러 번 호출하더라도 이전 호출에서 추가한 메모가 다음 호출에 남아 있지 않아야 합니다.

```python filename="12-09-memo_default.py"
def make_memo(text, memos=None):
  if memos is None:
    memos = []
  memos.append(text)
  return memos

print(make_memo("책 반납하기"))
print(make_memo("물 마시기"))
```

**실행 결과**

```text
['책 반납하기']
['물 마시기']
```

매개변수의 기본값을 [ ]로 두었다면 같은 기본 리스트가 다시 사용되므로, 두 번째 결과가 ['책 반납하기', '물 마시기']가 되었을 겁니다. 기본값을 None으로 바꾼 뒤 함수 안에서 새로운 리스트를 만들면 호출마다 서로 독립된 리스트를 사용할 수 있습니다. 직접 코드를 바꿔 실행해보면 차이를 분명하게 확인할 수 있습니다.

> **바로 핵심 요약**
>
> - b = a처럼 대입하면 값을 새로 복사하는 것이 아니라 두 이름이 같은 인스턴스를 가리키게 됩니다.
> - 리스트의 copy( )는 새로운 바깥쪽 리스트를 만들지만 내부에 있는 인스턴스는 원본과 공유합니다. 이를 얕은 복사라고 하며, 공유하는 안쪽 리스트나 딕셔너리의 내용을 변경하면 원본에서도 그 변화가 보입니다.
> - 안쪽까지 전부 복사하려면 copy 모듈의 deepcopy( ) 함수를 사용하고, 함수의 기본값에는 리스트 대신 None을 씁니다.
