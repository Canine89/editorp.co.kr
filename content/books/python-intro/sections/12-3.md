함수 안에 안쪽 함수를 정의하고, 함수를 인수로 전달하고, 함수 자체를 반환하는 문법은 실제로 어디에 사용될까요? 이번 절에서는 앞에서 배운 함수의 여러 특징이 실제 코드에서 어떻게 활용되는지 살펴보겠습니다. 에서 자세한 설명을 미뤄두었던 @property의 정체도 여기에서 만나게 됩니다.

> **미리 알아두세요!**
>
> - nonlocal로 안쪽 함수에서 바깥 함수의 변수를 바꿀 수 있습니다.
> - 함수 위에 붙는 @는 함수를 감싸 기능을 더하는 데코레이터입니다.

## 안쪽에서 바깥 함수 변수 바꾸기, nonlocal

안쪽 함수에서는 자신을 감싸고 있는 바깥 함수의 지역 변수를 읽을 수 있습니다. 그렇다면 안쪽 함수에서 그 변수의 값을 직접 바꾸려고 하면 어떻게 될까요? 먼저 아무런 처리를 하지 않고 시도해봅시다.

```python filename="12-10-nonlocal_error.py"
def make_counter():
  count = 0                # ➊ 바깥 함수의 변수

  def increase():
    count = count + 1      # ➋ 바깥 변수를 바꾸려고 시도
    return count

  return increase

counter = make_counter()
print(counter())
```

**실행 결과**

```text
UnboundLocalError: cannot access local variable 'count' where it is not
associated with a value
```

❶ 바깥 함수 make_counter( ) 안에 count 변수를 만들었습니다.

❷ 안쪽 함수 increase( )에서 count의 값을 1 늘리려고 했지만 오류가 발생했습니다. 앞에서 함수 안에서 전역 변수에 새로운 값을 대입하려 했을 때와 비슷한 이유입니다.

파이썬은 함수 안에 count = ...처럼 값을 대입하는 코드가 있으면 기본적으로 count를 그 함수의 지역 변수로 판단합니다. 따라서 increase( ) 안의 count는 바깥 함수의 count가 아니라 새로운 지역 변수로 취급됩니다. 하지만 count + 1을 계산하려는 시점에는 아직 이 지역 변수에 값이 들어 있지 않으므로 오류가 발생합니다.

이 문제를 해결하려면 increase( )에서 사용하는 count가 바깥 함수의 변수라는 사실을 파이썬에 알려주어야 합니다. 이때 사용하는 키워드가 nonlocal입니다. 코드를 작성하며 확인해봅시다.

![](/books/python-intro/p559-344.webp)

```python filename="12-11-nonlocal.py"
def make_counter():
  count = 0

  def increase():
    nonlocal count         # ➊ 바깥 함수의 count를 사용하겠다는 뜻
    count = count + 1
    return count

  return increase

counter = make_counter()
print(counter())
print(counter())
print(counter())
```

**실행 결과**

```text
1
2
3
```

❶ nonlocal count라고 적으면 increase( ) 안에서 사용하는 count가 새로운 지역 변수가 아니라 가장 가까운 바깥 함수의 count를 가리키게 됩니다. 따라서 호출할 때마다 count의 값이 1씩 늘어납니다.

## 리스트와 딕셔너리를 인수로 풀어 넘기기, 언패킹

함수를 다룰 때 유용한 문법을 하나 더 살펴보겠습니다. **리스트나 딕셔너리에 담긴 여러 값을 풀어서 함수의 인수로 한꺼번에 전달하는 방법입니다.** 이것을 **언패킹**이라고 부릅니다. 언패킹은 어렵게 생각할 것 없이 바로 코드를 실습해보면 이해가 되는 문법입니다.

```python filename="12-12-unpack_list.py"
def introduce(name, age, city):
  print(f"이름: {name}, 나이: {age}, 도시: {city}")

info = ["바로", 25, "서울"]
introduce(*info)           # ➊ 리스트를 하나씩 풀어서 전달
```

**실행 결과**

```text
이름: 바로, 나이: 25, 도시: 서울
```

❶ introduce(*info)에서 *는 리스트에 담긴 요소를 순서대로 하나씩 꺼내 함수에 전달합니다. 따라서 이 코드는 introduce("바로", 25, "서울")과 같습니다. 꺼낸 값은 순서대로 name, age, city 매개변수에 전달됩니다.

리스트처럼 여러 값을 순서대로 담고 있는 인스턴스를 풀어 전달할 때는 앞에 별표 하나(*)를 붙입니다. 딕셔너리는 조금 다릅니다. 딕셔너리에 들어 있는 값을 키워드 인수로 풀어 전달하려면 별표를 두 개(**) 붙입니다.

```python filename="12-13-unpack_dict.py"
def introduce(name, age, city):
  print(f"이름: {name}, 나이: {age}, 도시: {city}")

info = {"name": "요즘", "age": 30, "city": "부산"}
introduce(**info)          # ➊ 딕셔너리를 키워드 인수로 풀어서 전달
```

**실행 결과**

```text
이름: 요즘, 나이: 30, 도시: 부산
```

❶ introduce(**info)에서 **는 딕셔너리의 키와 값을 각각 키워드 인수로 풀어 함수에 전달합니다. 따라서 이 코드는 introduce(name="요즘", age=30, city="부산")과 같습니다. 이때 딕셔너리의 키 이름은 함수의 매개변수 이름과 같아야 합니다.

## 함수를 꾸며주는 @, 데코레이터

이제 함수를 인수로 전달하고 다른 함수를 반환하는 특징을 결합해, 기존 함수에 동작을 덧붙이는 데코레이터를 알아보겠습니다. 데코레이터라는 이름을 처음 들으면 '함수를 꾸민다'는 말이 조금 막연하게 느껴질 수 있습니다. 실제 코드를 통해 어떤 역할을 하는지 확인해봅시다. 예를 들어 "안녕하세요!"를 출력하는 greet( ) 함수가 있다고 해보겠습니다. 이 인사말의 위아래에 "------------------" 같은 줄을 출력해 조금 더 눈에 띄게 만들고 싶습니다.

**실행 결과**

```text
--------------------
안녕하세요!
--------------------
```

먼저 데코레이터 문법을 사용하지 않고, 앞에서 배운 함수를 인수로 전달하고 안쪽 함수를 반환하는 방식으로 작성해보겠습니다.

```python filename="12-14-wrap_manual.py"
def greet():
  print("안녕하세요!")

def with_line(func):       # ➊ 함수를 매개변수로 받아서
  def wrapper():           # ➋ 새 함수를 만들고
    print("-" * 20)
    func()
    print("-" * 20)
  return wrapper           # ➌ 그 함수를 돌려줍니다

greet = with_line(greet)   # ➍ 감싼 함수로 바꿔치기
greet()
```

**실행 결과**

```text
--------------------
안녕하세요!
--------------------
```

❶ with_line( )은 함수를 인수로 받습니다. 여기서는 greet 함수가 전달되어 func 매개변수에 저장됩니다.

❷ with_line( ) 안에 wrapper( )라는 안쪽 함수를 만듭니다. wrapper( )가 호출되면 구분선을 출력하고, func( )로 전달받은 greet( ) 함수를 실행한 뒤 다시 구분선을 출력합니다. 따라서 구분선 출력 → 인사말 출력 → 구분선 출력 순서로 동작합니다.

❸❶~❷를 통해 완성된 wrapper 함수를 반환합니다. 이때 wrapper( )가 아니라 wrapper라고 작성했으므로 함수를 바로 실행하는 것이 아니라, 나중에 호출할 수 있도록 함수 자체를 돌려줍니다.

❹ with_line(greet)이 반환한 wrapper 함수를 다시 greet에 저장합니다. 이제 greet( ) 함수를 호출하면 원래의 인사말만 출력되는 대신, 인사말의 위아래에 구분선까지 함께 출력됩니다.

코드는 의도한 대로 동작하지만, 기존 함수를 새로운 기능으로 감쌀 때마다 greet = with_line(greet)처럼 반환된 함수를 다시 변수에 저장해야 한다는 점이 조금 번거롭습니다. 파이썬에서는 데코레이터를 사용해 이 과정을 @로 간단하게 표현할 수 있습니다. 다음 코드에서 사용법을 알아봅시다.

```python filename="12-15-decorator.py"
def with_line(func):
  def wrapper():
    print("-" * 20)
    func()
    print("-" * 20)
  return wrapper

@with_line                 # ➊ greet = with_line(greet)과 같은 뜻
def greet():
  print("안녕하세요!")

greet()
```

**실행 결과**

```text
--------------------
안녕하세요!
--------------------
```

❶ 함수 정의 바로 위에 @with_line이라고 적으면, 파이썬이 greet = with_line(greet)을 대신 실행해줍니다. 실행 결과는 앞의 코드와 같습니다.

**이처럼 원래 함수 코드를 직접 수정하지 않고도 그 함수를 다른 함수로 감싸 새로운 동작을 더하는 기능을 데코레이터라고 합니다.** greet( )에는 인사말을 출력하는 코드만 두고, 인사말 위아래에 구분선을 출력하는 기능은 with_line( )이 맡습니다. 이름 그대로 기존 함수를 꾸며 주는 ‘장식’이라고 생각하면 됩니다. 함수의 본래 기능은 그대로 유지하면서 바깥에서 새로운 기능을 간편하게 추가할 수 있다는 것이 데코레이터의 장점입니다.

### 데코레이터는 어떻게 구성할까?

그렇다면 아무 함수나 데코레이터로 사용할 수 있을까요? 그렇지는 않습니다. 앞에서 만든 with_line( )의 구조를 다시 살펴보면 함수 데코레이터가 어떻게 동작하는지 더욱 분명하게 알 수 있습니다. 이 예제와 같은 데코레이터 함수를 만들려면 다음 세 가지 요소가 필요합니다.

1. 꾸밀 함수를 매개변수로 받습니다. 그 이유는 @를 붙인 함수를 넘겨받을 자리가 필요하기 때문입니다. 2. 기존 함수에 새로운 동작을 덧붙일 안쪽 함수를 만듭니다. 앞의 예제에서는 wrapper( )가 구분선을 출력하고 원래 함수인 greet( )을 호출합니다. 3. 겉 함수에서 wrapper 함수를 반환합니다. 반환된 함수가 원래 함수의 이름에 다시 저장되어, 이후에는 원래 이름으로 wrapper( )를 호출할 수 있습니다.

데코레이터를 처음 공부하면 이 세 가지 조건 중 세 번째를 가장 자주 빠뜨립니다. return wrapper를 작성하지 않으면 with_line(greet)은 None을 반환하고, 그 결과 greet에도 None이 저장됩니다. 이후 greet( )을 호출하면 None은 함수처럼 호출할 수 없으므로 TypeError: 'NoneType' object is not callable 오류가 발생합니다. 따라서 데코레이터를 만든 뒤 이 오류가 발생한다면 먼저 wrapper 함수를 제대로 반환했는지 확인하세요.

한 가지 더 살펴볼 점이 있습니다. 앞에서 만든 wrapper( )에는 매개변수가 없습니다. 따라서 지금 형태의 with_line은 greet( )처럼 인수를 받지 않는 함수에 사용하기에 적합합니다. 만약 인수를 받는 함수를 감싸고 싶다면 wrapper( )도 그 인수를 받아 원래 함수에 전달할 수 있도록 만들어야 합 니다.

처음 데코레이터를 만나면 구조가 다소 복잡하게 느껴질 수 있습니다. 지금은 직접 만드는 방법을 완벽하게 외우기보다 **@이름**이 함수 위에 붙어 있으면 해당 함수를 다른 함수로 감싸 어떤 동작을 덧붙이고 있다는 것을 읽어낼 수 있으면 충분합니다.

![](/books/python-intro/p564-345.webp)

> **NOTE**
>
> 데코레이터는 여기까지만 알아도 충분합니다. 인수를 받는 함수를 자연스럽게 처리하거나 데코레이터 자체에 값을 전

달하는 방법 등 더 다양한 형태도 있지만, 지금 단계에서는 @가 붙은 코드를 보았을 때 '이 함수에 다른 기능이 적용되고 있구나'라고 이해할 수 있으면 됩니다.

## 함수 다루기 연습하기

지금까지 nonlocal, 언패킹, 데코레이터를 차례대로 살펴봤습니다. 이번에는 짧은 예제를 직접 작성하며 각각의 특징을 다시 확인해봅시다.

## 연습 01 nonlocal로 점수 누적하기

먼저 nonlocal을 사용해 호출할 때마다 전달받은 점수를 누적하는 함수를 만들어봅시다.

```python filename="12-16-nonlocal_practice.py"
def make_scorer():
  total = 0                # ➊ 합계를 담을 바깥 변수

  def add(score):
    nonlocal total         # ➋ 바깥 변수를 사용하겠다는 뜻
    total = total + score
    return total

  return add

scorer = make_scorer()
print(scorer(10))
print(scorer(20))
print(scorer(30))
```

**실행 결과**

```text
10
30
60
```

❶ total은 make_scorer( )가 호출될 때 만들어지는 바깥 함수의 지역 변수입니다.

❷ nonlocal을 사용했기 때문에 add( )를 호출할 때마다 같은 total의 값을 변경할 수 있습니다. 따라서 점수를 차례대로 더하면 합계가 10, 30, 60으로 늘어납니다.

## 연습 02 언패킹으로 딕셔너리를 풀어 넘기기

주문 정보를 딕셔너리에 담아두고 함수에 한 번에 전달해봅시다.

```python filename="12-17-unpack_practice.py"
def order(menu, size, shots):
  print(f"{menu} {size} 사이즈, 샷 {shots}개")

info = {"menu": "아메리카노", "size": "톨", "shots": 2}
order(**info)              # ➊ 딕셔너리를 풀어서 전달
```

**실행 결과**

```text
아메리카노 톨 사이즈, 샷 2개
```

❶ **를 사용하면 딕셔너리의 각 항목이 키워드 인수로 풀려 전달됩니다. 이 예제에서는 딕셔너리의 키 menu, size, shots가 함수의 매개변수 이름과 같으므로 각각 알맞게 연결됩니다. 키 이름 하나만 달라도 오류가 나니 주의하세요.

## 연습 03 시작과 끝을 알려주는 데코레이터 만들기

이번에는 함수가 시작하고 끝날 때 안내 문구를 출력하는 데코레이터를 만들어봅시다. 함수 안의 코드는 건드리지 않습니다.

```python filename="12-18-decorator_practice.py"
def with_log(func):
  def wrapper():
    print("함수를 시작합니다.")
    func()
    print("함수를 끝냅니다.")
  return wrapper

@with_log                  # ➊ save_memo를 with_log로 감싸기
def save_memo():
  print("메모를 저장했습니다.")

save_memo()
```

**실행 결과**

```text
함수를 시작합니다.
메모를 저장했습니다.
함수를 끝냅니다.
```

❶ save_memo( )에는 메모 저장 안내를 출력하는 코드만 있으며, 함수의 시작과 끝을 알리는 문구는 with_log 데코레이터가 덧붙입니다. 같은 형태의 다른 함수에도 @with_log를 적용하면 그 함수를 실행할 때 같은 안내 기능을 추가할 수 있습니다.

> **바로 핵심 요약**
>
> - nonlocal은 안쪽 함수에서 가장 가까운 바깥 함수의 변수에 새 값을 대입할 때 사용하는 키워드입니다.
> - 함수를 호출할 때 리스트 앞에 별표 하나, 딕셔너리 앞에 별표 두 개를 붙이면 값을 풀어서 전달할 수 있습니다.
> - 데코레이터는 함수를 다른 함수로 감싸 기존 함수의 코드를 직접 수정하지 않고 새로운 동작을 적용할 때 사용할 수 있습니다.
> - @데코레이터이름은 데코레이터를 적용하는 문법이며, @property도 이러한 데코레이터 문법을 사용합니다.
